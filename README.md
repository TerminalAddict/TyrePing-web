# TyrePing website

Static website for **https://www.tyreping.com**. Plain HTML, CSS and JavaScript; no app server. A Python/`gh` publication step builds the downloads page and verifies the release APKs.

## Preview

Build the generated downloads first (`gh` must be installed and authenticated):

```sh
python3 scripts/sync_releases.py
python3 -m http.server 8080 --directory public
```

Open http://localhost:8080. Apache reads `public/.htaccess` in production for canonical redirects, the custom 404 response, cache policy, compression and security headers.

## Check and deploy

```sh
python3 -m unittest discover -s tests
bash scripts/deploy.sh
```

Deployment targets `paul@webhost2:/var/www/html/tyreping.com/`. The script synchronises both app channels, validates the site, backs up the existing directory outside the document root, and publishes `public/`. It uploads APK files before publishing links, then prunes only the generated `downloads/files/` directory to retain the selected builds. Other remote files are not deleted. Source, configuration, credentials and maintenance scripts are never published. Python 3.11+, authenticated `gh`, `flock`, SSH key authentication, rsync and curl are required on the publishing machine. `gh` and its credentials are not needed on the web server.

The backup path is printed during deployment. To restore a backup, SSH to the host and extract it into the web directory; restore or remove `.htaccess` as appropriate if reverting to a version without it. The initial deployment backs up the original placeholder page.

## App downloads and release sync

The public `/downloads/` page and its APKs are generated by `scripts/sync_releases.py`. Its source is `templates/downloads.html`, controlled by `config/distribution.json`. Generated `public/downloads/` and the local `.cache/releases/` cache are ignored by Git; do not commit APKs, manually edit generated pages or hard-code current versions in marketing pages.

**Refresh and publish app releases after publishing a new GitHub release:**

```sh
bash scripts/publish-downloads.sh
```

This is a one-command release publication process, not a running poller. Full website deployment also runs the sync automatically. Call this command from your app-release workflow after the GitHub release and assets are published, or run it manually. No cron job or scheduled workflow is installed.

The synchroniser:

1. Uses `gh api` to enumerate published releases from `TerminalAddict/TyrePing`, handling pagination. Chooses the most recently published stable release and pre-release independently, according to GitHub's `prerelease` flag. Drafts and unpublished releases are ignored. A pre-release can be older than the stable release; both channels keep their labels and dates.
2. Uses `gh release download` to fetch each selected release's `TyrePing-*.apk` and `SHA256SUMS.txt` into a private staging directory. Ambiguous/missing assets fail publication rather than silently selecting an older release.
3. Verifies asset sizes, GitHub's SHA-256 digests where supplied, the APK's published SHA-256 checksum, and the presence of AndroidManifest.xml in the APK. Cached files are checked again before reuse. Original signed APK bytes are never modified.
4. Generates `/downloads/` with the version, publication date, file size, checksum and release notes for each channel. GitHub Markdown links become their labels and bare GitHub URLs become `[project reference]` in both the page and its public JSON; the remaining notes are escaped as text. A missing channel displays an unavailable state. Browsers download only from tyreping.com, with no GitHub API calls or GitHub APK redirects.
5. Publishes verified assets before the HTML links; asset filenames live in unique release/hash directories to prevent channel/cache mixups. Only the generated binary directory is pruned after the new page is published. A failed fetch or verification leaves the published site unchanged. Old files may disappear after a new publication; reload Downloads to obtain the current build.

For a local-only rebuild:

```sh
python3 scripts/sync_releases.py
python3 scripts/check.py
```

The generated `downloads/releases.json` records channel metadata and hashes; no credentials are included. SHA checks verify that the mirror matches the project's published release files; app signing remains the responsibility of the app's release process. Website and downloads publications share a lock to prevent concurrent uploads.

## Switching to Google Play

Once the real listing is public, change `config/distribution.json`:

```json
{
  "mode": "play-store",
  "github_repository": "TerminalAddict/TyrePing",
  "play_store_url": "https://play.google.com/store/apps/details?id=nz.paulwillard.tyreping"
}
```

The URL above is the intended package URL, not a claim that the listing is already live. Then run `bash scripts/deploy.sh`. Play Store mode performs no GitHub fetch, replaces APK choices with a Google Play button, removes the generated hosted APKs during publication, and blocks the former `/downloads/files/` paths. Visitors see pricing and purchase options on Google Play; the site does not invent a price. The same `/downloads/` link is used by the homepage and navigation in either mode. The manual APK guide remains documentation for sideloading.

This stops this website distributing the mirrored APKs; it cannot withdraw files visitors have already downloaded. Backups outside the public web directory and the local release cache are not served by Apache.

## Content maintenance

Keep product copy independent of numbered app releases. The generated downloads page owns versions and channel status. `SoftwareApplication` JSON-LD links to the local downloads page without pinning `softwareVersion`. The validator rejects hard-coded app versions in the main marketing/install pages, GitHub URLs throughout public HTML/metadata, release JSON and our attribution summary, and verifies the locally hosted APKs against the generated manifest.

The homepage separates core ride tools from the inventory, sensor-health, fleet and monitoring additions available for pre-release testing. The install guide covers those workflows, towing/insights, reporting, retention and manual update checks. Keep build-availability wording, FAQ answers and structured feature lists aligned when promoting features to stable. Website downloads remain local; the app’s separate Debug-only, manually triggered external update checker is explained in the install and privacy pages.

Review the app README when capabilities or workflows change, keep visible FAQs and their JSON-LD answers identical, and use the downloads page for release notes. Public navigation and help links stay on tyreping.com until store mode is enabled. Upstream names, project identifiers, contribution references and reviewed commits remain as plain text. Preserve original third-party licence notices and signed APK bytes; the font's unmodified OFL notice is offered as a download. GitHub remains a private publication source, not a public website destination.

## Screenshots

Original captures are preserved in `tyreping screenshots/`. The supplied captures show an earlier development build, labelled accordingly on the homepage; they do not illustrate every current feature. The homepage uses actual car and tandem-axle trailer screens in its hero and includes a gallery of all seven supplied captures. Each screen has 540px and 1080px WebP assets in `public/assets/images/screenshots/`, descriptive alt text, intrinsic dimensions and a full-size link. Clicking a screenshot (including either hero image) or its full-size link opens an accessible modal with previous/next controls, arrow keys, touch swipes and a zoom control for viewing the original 1080px image. Escape, the close button or the backdrop closes the modal and restores focus. Direct image URLs remain available without JavaScript. Below-the-fold gallery images are lazy-loaded. The gallery works as a static collection without JavaScript; JavaScript adds a screenshot selector. Screenshots show example readings, not live sensor data or recommended settings.

When replacing screenshots, keep the original aspect ratio, update both WebP sizes, and update the `SoftwareApplication.screenshot` entries in homepage JSON-LD. Use a new asset filename for changed images to avoid stale browser caches. Keep the screenshot count, gallery labels and descriptions consistent.

The dedicated `/licenses/` page credits TPMS Advanced (Vincent Masselis and contributors) and Persistent TPMS (aveshev and contributors), reproduces the complete Apache 2.0 licence, and links downloadable licence and attribution text. Both checked upstream `develop` snapshots have identical licence files and no `NOTICE`/`NOTICE.*` file. Their reviewed commit IDs are recorded on the page and in `public/licenses/ATTRIBUTIONS.txt`; update this information when incorporating new upstream code. Keep copyright and attribution notices intact. The page also links the website font's OFL notice. This website page does not package notices into an Android APK; maintain the app's own bundled licence/notices when releasing it.

- App artwork is copied from TyrePing's `mipmap-xxxhdpi/ic_launcher.png`; favicon and social-card derivatives use that icon. Preserve its provenance and branding.
- Manrope variable font is self-hosted; its licence is in `public/assets/fonts/OFL.txt`.
- Interface icons and vehicle illustrations are native SVG.
- Pages include canonical metadata, Open Graph and Twitter cards, and JSON-LD. There are no invented reviews, ratings, prices or store listings.
- `robots.txt`, `sitemap.xml`, `site.webmanifest`, Apple/Android icons, a maskable icon, PNG favicons and multi-resolution ICO are included.
- No analytics, ads, forms, external embeds, cookies, browser storage or service worker. The website privacy page describes hosting access logs, APK downloads and external links; the separate app policy describes Android data handling and external services.

Change sitemap `lastmod` only for pages whose content changed. Run checks and test mobile navigation, FAQ disclosure, the screenshot selector and download links before deploying. `scripts/check.py` uses only Python's standard library.
